------------- MANEJO DE LA ASINCRONIA
las funciones que requieran programacion asincrona deben declararse como async def
Para hacer uso de "await".
Se ejecutan con asyncio.run(func_asincrona(arg))
Ya que al ser llama, no se ejecuta inmediatamente. 
En su lugar, devuelve un objeto "corrutina" (tipo de promesa que representa un trabajo a futuro).

asyncio.run(): Es una función de la librería asyncio que actúa como un "motor" o "lanzador" 
de la funcion asíncrona, la prepara para ejecutarse. Crea un Event Loop, que corre en segundo plano 
y se encarga de gestionar todas las tareas pendientes por resolver (como esperar una respuesta de Internet).
Cuando encuentra un await (como await bot.send_message(...)), el bucle no se queda esperando sin hacer nada. 
Le dice a Telegram: "Oye, avísame cuando tengas la respuesta", y se pone a hacer otras cosas. 
Cuando Telegram responde, el bucle reanuda tu función.
Finalmentem Cierra el bucle y devuelve el resultado: Una vez que enviar_mensaje_terminal ha terminado 
su ejecución (o ha dado un error), asyncio.run cierra el bucle de eventos de forma segura.



--------------from telegram.ext import Application, CommandHandler, MessageHandler, filters, ContextTypes  
Application → contenedor principal que maneja TODOS los handlers.
app = Application.builder().token(TOKEN).build()
app.add_handler(CommandHandler(...))
app.add_handler(MessageHandler(...))
# El bot "escucha" permanentemente y ejecuta el handler adecuado
app.run_polling(# Inicia el bot y lo pone a escuchar mensajes de Telegram.
    allowed_updates=Update.ALL_TYPES,  # ✅ Escucha TODOS los tipos de actualizaciones
    drop_pending_updates=True          # ✅ Ignora mensajes antiguos pendientes
)
Polling = El bot pregunta constantemente a Telegram: "¿Hay nuevos mensajes para mí?"

Inicias el bot
    ↓
El bot se conecta a Telegram
    ↓
Bucle infinito:
    1. Pregunta: "¿Hay nuevos mensajes?"
    2. Telegram responde: "Sí, aquí están"
    3. El bot procesa los mensajes
    4. Vuelve al paso 1

CommandHandler → Maneja comandos (palabras que empiezan con /)
CommandHandler("start", start)
async def start(update: Update, context: ContextTypes.DEFAULT_TYPE):
    await update.message.reply_text("🤖 ¡Bot activo! Envía cualquier mensaje.")

MessageHandler → Maneja mensajes (textos, fotos, etc.)
MessageHandler(filters.TEXT & ~filters.COMMAND, handle_message) ## Cuando el usuario escribe texto → ejecuta handle_message()


filters → filtros para decidir qué mensajes manejar.
filters.TEXT      # Solo mensajes de texto
filters.PHOTO     # Solo fotos
filters.COMMAND   # Solo comandos (/start, /help)

ContextTypes → tipo de contexto que recibe tu función.
context: ContextTypes.DEFAULT_TYPE # Permite guardar datos entre mensajes


Handler = "Manejador" o "Controlador". Es una función o clase que "maneja" un evento específico.
Un handler es un "escuchador" que reacciona cuando ocurre algo:
EVENTOS: Usuario escribe: 
algo           → MessageHandler → Procesa el mensaje
envía una foto → MessageHandler con filters.PHOTO → Guarda la foto 
/start         → CommandHandler → Ejecuta una función
/help          → CommandHandler → Muestra ayuda

Otros manejadores de eventos:
CallbackQueryHandler	Botones inline	    Clic en botón
InlineQueryHandler	    Consultas inline	@bot consulta
PollHandler	            Encuestas	        Respuestas a encuestas
PreCheckoutQueryHandler	Pagos	            Confirmación de pago
ShippingQueryHandler	Envíos	            Dirección de enví

los handlers acepten exactamente 2 parámetros, aunque el 2do (contexto) no se ocupe. 
async def handler(update: Update, context: ContextTypes.DEFAULT_TYPE):
    #                    ↑ obligatorio    ↑ obligatorio

async def handle_message(update: Update, context: ContextTypes.DEFAULT_TYPE):
async def start(update: Update, context: ContextTypes.DEFAULT_TYPE):
estas funciones son manejador, por eso tienen los 2 parametros, como se ve a continuacion.
app.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, handle_message))

Update es un objeto que contiene toda la información de la interacción del usuario con el bot.
Usuario escribe "Hola" al bot
         ↓
Telegram envía la información
         ↓
La librería crea un objeto Update con:
         ├── message: {
         │    ├── text: "Hola"
         │    ├── from_user: { username: "Edily" }
         │    ├── chat: { id: 1528883207 }
         │    └── date: "2026-07-13"
         │ }
         ├── update_id: 123456789
         └── ...
         ↓
El Update se pasa al handler
         ↓
Puedes acceder a todo con `update.`

Código	                        Acceso a
update.message.text	            El texto del mensaje
update.message.chat.id	        Chat ID del usuario
update.effective_user.username	Username de Telegram
update.message.date	            Fecha y hora del mensaje
update.message.reply_text()	    Responder al mensaje
update.callback_query.data	    Datos de botón inline
update.edited_message	        Mensaje editado
update.poll	                    Encuesta respondida
